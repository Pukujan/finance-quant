# AGENTS.md — finance-quant operating contract

This repository is a local quantitative research, historical point-in-time evaluation, adaptive strategy/portfolio, and zero-capital simulated paper-trading workstation. Agents are implementation/research workers; empirical market outcomes and executable product semantics judge research usefulness.

## Mandatory read order

Before making a material change, read in this order:

1. `AGENTS.md`
2. `docs/CURRENT_STATE.md`
3. `docs/handoffs/SESSION_2026-08-28_ADAPTIVE_QUANT_ENGINE.md` when present/current
4. the active GitHub master/architecture/child issue referenced by current state
5. `docs/handoffs/LATEST.md`
6. relevant contracts/specs and affected implementation/tests

If these sources conflict, resolve the conflict in durable project state before implementation.

## Authority hierarchy

1. Live-capital/safety restrictions in this file and explicit human instructions.
2. Active product/architecture issue acceptance criteria and shared public contracts.
3. Executable product-correctness properties/tests for PIT, experiment identity, outcomes, paper accounting, strategy/portfolio intent, and integration behavior.
4. Implementation details.
5. Research/signal/model/KG/state outputs.

Research metrics, model output, UI state, agent claims, or framework state never outrank fixed PIT/evaluation/account semantics.

## Hard rules

- Preserve point-in-time semantics: no feature, signal, graph edge, document, claim, source score, universe membership, label, router input, model input, portfolio decision, or paper action may use information before its legitimate `known_at` time.
- Historical corpus filtering happens before retrieval/ranking/embedding results can influence a decision-time state, signal, feature or prediction.
- Do not inspect, copy, expose, or optimize against sealed hidden holdout cases/labels unless an explicit current issue grants access.
- Do not add or enable brokerage credentials, live capital, or live order authority. Local simulated paper trading is allowed; broker/live capital remains out of scope.
- Failed, crashed, invalid, rejected, superseded, and losing research attempts remain in durable lineage, including strategy/model/provider variants generated by automated search.
- Never weaken/delete a correctness test merely to make a change pass. If the semantic contract changes, update the durable issue/spec and oracle deliberately.
- A signal/model/KG/state/meta/portfolio lane may propose outputs; canonical historical snapshots, realized labels, scoring, experiment identity, and paper-account truth are owned by the fixed laboratory/control plane.
- Do not collapse factual confidence, market attention, economic materiality, exposure strength, predictive usefulness, model calibration and portfolio confidence into one generic confidence number.
- Do not make MarketState/KG/RAG/news mandatory merely because they are sophisticated. They are optional signal-provider families and may empirically receive zero weight.

## OSS adoption rule

Prefer `upstream pinned dependency -> thin adapter -> constrained extension -> fork only as last resort`.

A local fork requires a concrete product reason and a bounded adapter/patch surface. Do not copy mature frameworks into this repo when a dependency or adapter suffices. Do not introduce distributed infrastructure merely because the architecture could scale someday; local workload must justify it.

## Vertical-slice rule

New predictive capabilities should be delivered through the adaptive engine as:

`real/PIT inputs -> versioned signal/provider artifact -> forecast/model/meta weighting -> PortfolioIntent -> walk-forward/outcome -> forward paper -> evidence/metrics -> workstation visibility`

A MarketState/KG/RAG provider may have its own internal evidence/state pipeline, but the permanent product spine must also support simple price/momentum/breakout/volatility strategies without any knowledge graph.

The frontend is an operator/research surface only. It never owns fills, paper-account truth, historical labels, PIT filtering, experiment identity, or live-capital authority.

## Specification and testing contract

For material capabilities:

- reference the active GitHub issue;
- define or preserve the shared public interface/semantics before or with implementation;
- add the cheapest executable tests that can credibly falsify bugs that would invalidate research or paper execution;
- prefer deterministic unit/integration tests plus property/metamorphic tests for time, replay, dedup, cache, DAG, router/meta weights, portfolio and concurrency semantics;
- use targeted mutation testing for critical semantic modules where small operator mistakes could silently corrupt results;
- use small hidden black-box product scenarios only when they add information beyond visible tests;
- use Lean/SMT/formal methods only for a concrete hard invariant/state-machine/constraint problem that executable tests cannot credibly cover.

Do not recreate the former assurance-phase ladder as the product roadmap. Tests exist to catch real product/research-integrity bugs, not to grant abstract capability authority.

Correctness gates software merges. Noisy alpha/performance metrics ordinarily gate research promotion rather than code merging.

## Automated strategy-search rule

AI coding makes candidate generation cheap and therefore raises the risk of backtest/data-mining overfitting.

- Preserve attempted strategy/provider/model/policy genealogy, not only winners.
- Do not select a strategy solely because it is the maximum Sharpe/return among a large historical search.
- Keep strict walk-forward chronology and prior-resolved-only meta weighting.
- Use appropriate multiple-testing/backtest-overfitting discipline for research promotion.
- Start immutable prospective paper history as soon as an executable strategy/policy is valid.
- The system must be allowed to set a sophisticated provider's active weight to zero when evidence does not support it.
