# Spike #11 — Fast local pattern model and paper-trading gate

**Question:** Can a small local neural/neurosymbolic model pre-check information, recognize trading patterns, and propose or veto paper trades without weakening the project’s temporal, cost, or evidence boundaries?

**Status:** **PROPOSED — Phase C / post-Phase-B spike; owner decision required.** This memo does not authorize model training, paper trading, or changes to the Phase B vertical slice. It defines a bounded experiment to evaluate after the Phase B exit criteria and the Phase C sealed-holdout/adversarial gate are satisfied.

**Boundary:** `finance-quant` owns the quantitative research/trading laboratory. Qlib/MLflow may provide training and lineage artifacts; LEAN remains the execution/backtest/paper-trading boundary; FOSSIL stores reviewed definitions, evidence, and provenance, not numerical hot-path values.

**Related work:** Phase B plan; spike #6 / issue #6 (ontology and PIT-safe graph features); spike #9 / issue #9 (sealed holdout and adversarial acceptance); issues #2, #4, #5, and #10 for PIT storage, experiment lineage, LEAN replay, and native orchestration.

---

## 1. Motivation and scope

The user idea is a fast local model that acts as a **pre-checker and constrained signal proposer**. It may summarize already-authorized information, recognize patterns, score a candidate trade, and either propose the trade or veto it. It is not an autonomous trader, an authority for market data, or a replacement for the Phase B baselines, PIT store, Qlib/MLflow lineage, LEAN cost model, or human risk control.

This is a **Phase C / post-Phase-B research spike** because Phase B explicitly excludes automated model search, model training, graph-neural-symbolic experiments, and paper trading. The first implementation target should be deliberately small: one local model, one fixed universe, one signal horizon, one deterministic feature contract, and one LEAN replay path.

### Non-goals

- No live trading, broker credentials, or unattended order submission.
- No broad alpha search or model zoo before the smallest prototype is understood.
- No use of current/latest data when an as-of query is required.
- No graph database, online knowledge graph, or global graph recomputation as a prerequisite.
- No claim that a pattern detector is useful merely because it has high rank IC or predictive accuracy.

---

## 2. Prerequisites and entry criteria

The spike may enter implementation only after the relevant Phase B artifacts exist and are reviewable:

1. **Real canonical fixture:** a pinned manifest hash and a documented data vendor/universe, with bitemporal records and reproducible ingest.
2. **Explicit cost model:** named fill, slippage, fee, and cost-stress parameters, including the Phase B nominal and 2x-slippage comparisons.
3. **LEAN replay:** a deterministic replay path that consumes signals and emits a receipt with execution assumptions and an equity-curve/result hash.
4. **Sealed holdout:** issue #9’s sealed mini-holdout and acceptance harness, with labels inaccessible to the training/proposer workflow and the documented SEAL-A/SEAL-B counters.
5. **Baseline evidence:** B1–B5 and the Qlib/MLflow path have run through native orchestration, with reproducible receipts and failure visibility.
6. **Feature authority:** every input feature is traceable to a manifest, feature IR/configuration, and an as-of query contract. Graph features additionally satisfy spike #6’s boundary.

A synthetic fixture may be used for plumbing tests, but it cannot establish trading merit or unlock paper trading.

## 3. Smallest viable prototype (SVP)

### 3.1 Interface

At each evaluation instant `t`, the prototype consumes a frozen, versioned feature packet produced by Phase B infrastructure:

- PIT-safe prices, returns, volume, and corporate-action-adjusted fields;
- outputs from one or more B1–B5 baselines and/or the Qlib baseline;
- optional graph features from the approved static fixture or bitemporal graph-feature namespace;
- explicit position, exposure, liquidity, and trading-cost context known at `t`;
- a feature packet identifier, dataset manifest hash, feature-IR/config hash, and `kt_bound`.

It returns a typed decision, not an order:

```text
PASS | VETO | PROPOSE
score, confidence_or_margin, rationale_id, model_artifact_hash,
feature_packet_hash, decision_time, valid_until, risk-check inputs
```

`PROPOSE` is a candidate signal for the existing strategy/execution path. `VETO` can suppress a candidate generated by a baseline. `PASS` means no action by this model. The prototype must not bypass the portfolio/risk layer or directly submit an order.

### 3.2 Deliberately narrow experiment

- One liquid, survivorship-controlled universe already covered by the canonical fixture.
- One rebalance frequency and one forecast/holding horizon.
- One candidate-generation policy, preferably an existing B1–B5 signal.
- One frozen feature schema and one training split policy.
- A small local artifact that can run within the research workstation’s latency/resource budget; benchmark wall-clock latency and memory rather than assuming “fast.”
- Compare **baseline alone**, **baseline plus model veto**, and **baseline plus model proposal** under the same LEAN replay and cost assumptions.

The first success criterion is not autonomous profitability. It is deterministic, auditable, PIT-safe gating whose cost-aware out-of-sample results justify a second experiment.

## 4. Data boundary and PIT/`kt` safety rules

1. **As-of inputs only.** At evaluation instant `(vt=t_v, kt=t_k)`, every feature must be read as `AS OF (t_v, t_k)`. No `latest`, future revision, future close, or post-decision correction may enter the packet.
2. **Labels are future-relative and isolated.** Labels may use outcomes after `t` only in training/evaluation construction. They must never be present in serving inputs, feature normalization, threshold selection, early stopping, or rationale generation.
3. **Split by time and identity.** Training, validation, test, and sealed holdout boundaries are declared before fitting. Prevent overlap from rolling windows, duplicate instruments, revisions, corporate actions, and normalization statistics. The sealed holdout is never used for tuning.
4. **Graph features are as-of filtered first.** Per spike #6, build `G(t_v,t_k)` by filtering node/edge validity before projection, aggregation, embedding, or learned inference. Never compute a full-horizon graph and backfill historical features.
5. **Graph artifacts carry their own bound.** An embedding/GNN/model artifact must be versioned with a run record and dataset `kt_bound`; serving requires that bound to be no later than the decision `kt`. Numeric graph-feature values land in the PIT store as ordinary `graph_feature` records with their own `vt/kt`.
6. **No survivorship.** Universe membership and delisted instruments follow the historical fixture as-of the relevant instant, not today’s constituents.
7. **No leakage through operations.** Fit scalers, encoders, feature selection, thresholds, calibration, pattern vocabulary, and DSL/embedding parameters on training data only. Cache keys include the temporal bound and manifest/config hashes.
8. **Evidence is by reference.** FOSSIL may hold the feature definition, model identity, decision, and review trail; numeric values remain in the PIT/experiment artifacts. Every result references the source hashes and cost model.
9. **Fail closed.** Missing, stale, ambiguous, or temporally unbounded inputs produce `VETO`/no-trade and an explicit receipt, never an inferred value.

A poison test must inject a late-announced edge, revised observation, and post-period constituent and demonstrate that the model cannot observe them before their `kt`.

## 5. Candidate model forms

| Form | Role in the SVP | Strength | Main risk / constraint |
|---|---|---|---|
| Small neural network (MLP/1-D temporal model) | Score a fixed feature vector or short, fixed window | Fast inference; handles nonlinear interactions | Easy to overfit; strict split and calibration discipline |
| Decision tree / shallow ensemble | Interpretable score or veto | Strong baseline, inspectable rules, low serving cost | Instability and threshold mining |
| Explicit rule gate | Hard safety/pattern veto | Auditable and fail-closed | Limited recall; rules can encode hidden lookahead |
| Neurosymbolic DSL + embedding | Symbolic eligibility/risk gate plus compact learned representation | Separates hard constraints from learned similarity | Highest complexity; DSL temporal effects and embedding `kt` must be checked |

Recommendation: start with a shallow tree or small MLP behind explicit rule gates. Treat the neurosymbolic form as a follow-on only if it beats that control while preserving inspectability and temporal proofs. Any rule/pattern grammar must be versioned and checked by the project’s feature/IR boundary rather than interpreted as informal prose.

## 6. Offline evaluation before paper trading

Evaluate on chronological validation/test periods and then the sealed holdout through the issue #9 procedure. Report confidence intervals or block-bootstrap uncertainty where appropriate, plus the number of decisions and abstentions.

### Predictive and decision metrics

- Precision/recall or balanced accuracy for veto/proposal decisions, with calibration (Brier score and reliability curve).
- Coverage/abstention rate, veto rate, proposal rate, and stability across instruments and regimes.
- Incremental rank IC, information ratio, hit rate, and turnover versus the unchanged baseline.
- Cost-aware return, Sharpe/Sortino, drawdown, tail loss, turnover, capacity/liquidity usage, and degradation under nominal and 2x-slippage costs.
- False-positive vetoes and false-negative proposals, especially around gaps, corporate actions, and data-quality incidents.
- Determinism: identical inputs/configuration produce identical decision and receipt hashes.
- Operational measures: local inference latency, memory/CPU use, startup behavior, and fail-closed behavior.

A model fails the offline gate if its apparent benefit disappears under costs, time/identity splits, perturbation tests, or the sealed holdout; if it relies on unreviewed feature sources; or if it cannot emit a complete lineage and temporal-safety receipt. Accuracy alone is not a promotion metric.

## 7. Paper-trading gates and safety limits

Paper trading is a later controlled observation phase, not the next automatic step. It requires owner approval after offline results and sealed-holdout review.

### Promotion gates

1. Phase B exit criteria and the Phase C adversarial acceptance pass.
2. No unresolved PIT/`kt` poison-test failures, unexplained data gaps, or nondeterministic receipts.
3. Pre-registered model/config/feature/cost hashes and a reviewable FOSSIL evidence commit.
4. Positive and stable **incremental** evidence versus the baseline under realistic costs, with no unacceptable tail/drawdown regression.
5. LEAN replay matches the paper-trading adapter’s signal and risk semantics on a dry run.
6. Human owner explicitly approves the bounded paper campaign; approval expires with the model/config or data-contract change.

### Mandatory controls

- Paper-only account/environment; no live credentials or live-order capability in the prototype.
- Hard kill switch checked before every decision batch and independently monitored.
- Global daily loss, drawdown, turnover, order-count, notional, and stale-data limits.
- Per-instrument position/notional limits, liquidity participation limits, maximum leverage, and maximum concurrent positions.
- Human approval for campaign start, model promotion, limit changes, and any exceptional/manual override.
- Default-deny on missing heartbeat, stale input, unknown symbol, risk-check failure, model/hash mismatch, or clock/`kt` inconsistency.
- Immutable decision/order-intent receipts and alerts for every veto, rejection, kill-switch event, and limit breach.
- Automatic expiry/rollback to the last approved baseline; no self-retraining or threshold changes during the campaign.

The paper campaign must have a fixed duration, universe, schedule, and stop conditions, and must be reviewed before extension.

## 9. Decision

**PROPOSED:** defer this experiment until Phase B exits and Phase C sealed-holdout/adversarial acceptance is available; then begin with a shallow tree or small MLP used only as a fail-closed proposal/veto layer over an existing baseline. Adopt the strict as-of data and graph rules above, retain LEAN as the execution truth, and require cost-aware offline evidence plus explicit human approval before any bounded paper campaign.

**Next decision gate:** after Phase B completion and issue #9 acceptance, the owner decides whether to authorize the SVP. The authorization must name the fixture manifest, universe, horizon, feature schema, model form, cost model, holdout epoch/counters, paper-trading limits, human approver, and kill-switch operator. If those artifacts are not available, the decision remains **DEFER**.
